# Теория — центральная идентичность (lite)

## Зачем

Локальные учётки на каждом хосте не масштабируются. Mid+ минимум:

- каталог пользователей и групп (LDAP);
- клиент хоста (**SSSD**) кэширует и отдаёт NSS/PAM;
- `getent passwd` видит доменных пользователей;
- sudo и группы централизованы или согласованы;
- **break-glass**: локальный admin, чтобы не потерять хост при падении LDAP.

## Архитектура lab

```text
srv: OpenLDAP (slapd)  +  опционально SSSD (клиент к себе)
cli: SSSD → ldap://srv   →  ssh login доменным user
```

Альтернатива: **FreeIPA** на одном хосте (ipa-server) — допустима, если укладываетесь по RAM и времени; в выводах укажите стек. Реплика и полный trust не нужны.

## Что проверить на практике

| Проверка | Команда / факт |
|----------|----------------|
| NSS | `getent passwd alice` возвращает строку |
| Группы | `id alice` / `getent group ops` |
| SSH | вход `alice@cli` ключом или учебным паролем lab |
| sudo | правило для доменной группы **или** явный local sudoers |
| Кэш | краткий outage LDAP: кэшированный login ещё работает (если настроено) |
| Break-glass | локальный `labadmin` с sudo, когда LDAP down |

## Риски

- Сломать PAM → потеря SSH: снимок + консоль гипервизора.
- Не открывайте LDAP наружу lab-сети.
- Пароли только учебные; в документе передачи смены не светите.

Связь с модулем **03**: least privilege сохраняется — доменный user ≠ root.
