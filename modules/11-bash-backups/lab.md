# Лаборатория 11 — скрипты и бэкапы

## Цель

Сделать регулярный бэкап критичных путей, ротацию копий, проверку целостности и доказанное восстановление (файл + каталог).

## Окружение

- `srv` с `/srv/data` (модуль 05) и службами (модуль 10)
- Права root на каталог бэкапов

## Задания

### 1. Inspect — что бэкапим

Составьте список восстановления учебного стенда и сохраните в `~/lab-notes/11-scope.txt`:

- конфиги nginx (`/etc/nginx/...`)
- `/etc/exports`, файлы `/etc/sudoers.d/` лабораторные
- контент сайта `/var/www/lab`
- данные NFS share
- unit-файлы lab-* в `/etc/systemd/system/`
- список пакетов (`dpkg -l` / `rpm -qa`)
- (по желанию) `/etc/ssh/sshd_config.d/99-lab-hardening.conf`

### 2. Change — скрипт бэкапа

Создайте `/usr/local/bin/lab-backup.sh` с `set -euo pipefail`:

- каталог `/srv/data/backups/$(date +%F-%H%M%S)`;
- копирует выбранные пути через `rsync -a` **или** `tar czf`;
- сохраняет манифест пакетов;
- пишет лог `/var/log/lab-backup.log`;
- ротация: оставлять последние **N=5** копий;
- ненулевой код при ошибке;
- режим `--dry-run` (только показать, что было бы скопировано).

Права на `/srv/data/backups`: только root (`700` или `750`).

### 3. Verify — dry-run и боевой прогон

```bash
sudo /usr/local/bin/lab-backup.sh --dry-run | tee ~/lab-notes/11-dry-run.txt
sudo /usr/local/bin/lab-backup.sh | tee ~/lab-notes/11-backup-run.txt
sudo ls -lah /srv/data/backups
```

### 4. Change — расписание

`lab-backup.service` + `lab-backup.timer` (учёба: каждые 30–60 минут; в заметках укажите, что в проде обычно nightly + offsite).

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now lab-backup.timer
systemctl list-timers | grep lab-backup
```

### 5. Verify — восстановление файла

1. Запустите бэкап.
2. Удалите **тестовый** файл из сайта или share (не конфиги целиком).
3. Восстановите из последней копии.
4. Шаги — в `~/lab-notes/11-restore-file.md`.

### 6. Verify — восстановление каталога и негативный тест

1. Создайте каталог с несколькими файлами в share, сделайте бэкап.
2. Удалите каталог, восстановите **целиком**.
3. Негатив: попробуйте восстановить из **несуществующего** timestamp — скрипт/ручной процесс должен явно ошибиться (зафиксируйте).
4. Запишите в `~/lab-notes/11-restore-dir.md`.

### 7. Change — проверка целостности (простая)

После бэкапа сохраняйте `sha256sum` (или `find … -type f | cpio` + checksums) ключевых файлов в `MANIFEST.sha256` внутри каталога бэкапа.  
После восстановления — `sha256sum -c` для одного файла.

### 8. Verify — инъекция сбоя

1. Временно укажите в скрипте несуществующий source-путь.
2. Убедитесь, что бэкап падает с ненулевым кодом и пишет ошибку в лог.
3. Верните путь.

### 9. Automate — отчёт о последних бэкапах

`/usr/local/bin/lab-backup-report.sh` печатает: список копий, размер, дату, возраст самой свежей. Если свежее N часов нет — exit 1.

### 10. Document

Политика в `~/lab-notes/11.md`: что / куда / как часто / как проверить / RPO-RTO словами новичка.

## Критерии приёмки

- [ ] Скрипт создаёт датированный бэкап и поддерживает dry-run
- [ ] Timer запускает бэкап
- [ ] Ротация старых копий работает
- [ ] Восстановлены тестовый файл и каталог
- [ ] Есть MANIFEST/checksum и негативный тест сбоя
- [ ] Есть report-скрипт и политика в заметках

## Подсказки

| Семья | Список пакетов |
|-------|----------------|
| Debian/Ubuntu | `dpkg -l` |
| Rocky/Alma | `rpm -qa` |

- Не бэкапьте весь `/` в первой версии.
- Бэкап на тот же диск не спасает от смерти диска — для курса достаточно; в политике это упомяните.

## Очистка

Оставьте скрипт, timer и хотя бы один бэкап для капстоуна.
