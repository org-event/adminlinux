# Лаборатория 11 — скрипты и бэкапы

## Цель

Сделать ежедневный (или частый учебный) бэкап критичных путей и проверить восстановление одного файла.

## Окружение

- `srv` с `/srv/data` (модуль 05) и службами (модуль 10)

## Задания

### 1. Inspect

Составьте список того, что нужно сохранять для восстановления учебного стенда:

- конфиги nginx
- `/etc/exports`, sudoers.d lab-файлы
- контент сайта
- данные NFS share
- список установленных пакетов

### 2. Change — скрипт

Создайте `/usr/local/bin/lab-backup.sh`:

- создаёт каталог `/srv/data/backups/$(date +%F-%H%M)` (или подобный);
- копирует выбранные пути через `rsync` или `tar`;
- сохраняет `dpkg -l` / `rpm -qa`;
- пишет лог;
- удаляет старые бэкапы старше N копий (например, оставлять 5);
- возвращает ненулевой код при ошибке.

### 3. Change — расписание

Оформите `lab-backup.service` + `lab-backup.timer` (для учёбы — каждые 30–60 минут; в заметках укажите, что в проде обычно nightly).

### 4. Verify — восстановление

1. Запустите бэкап вручную.
2. Удалите **тестовый** файл из сайта или share (не всю систему).
3. Восстановите его из бэкапа.
4. Зафиксируйте шаги в `~/lab-notes/11-restore.md`.

### 5. Document

Политика бэкапа в `~/lab-notes/11.md`: что/куда/как часто/как проверить.

## Критерии приёмки

- [ ] Скрипт создаёт датированный бэкап
- [ ] Timer запускает бэкап
- [ ] Есть успешное тестовое восстановление файла
- [ ] Есть ротация старых копий
- [ ] Политика описана в заметках

## Подсказки

- Не бэкапьте «весь `/`» в первой версии — узкий список надёжнее.
- Права на `/srv/data/backups` ограничьте root.

## Очистка

Оставьте скрипт и хотя бы один бэкап для капстоуна.
